# 书源：OPDS 书目与 WebDAV 文件夹

> 状态：第一期已做。本文记录方案和取舍。

## 为什么只做这两种

曾考虑兼容“阅读”（Legado）的网页书源。2026 年 5 月，该项目删除了全部内容，只留一则公告，称项目涉及侵权、作者已承担法律责任；
有报道称开发者因侵犯著作权被判刑。它的书源生态几乎都指向盗版站，兼容它的格式就是为了接上这些书源，风险落在发布者身上。
所以灵阅不做网页抓取，只接两种本来就用来分发电子书的来源：

- **OPDS 书目**：电子书目录的开放标准。Calibre-web、Komga、Kavita 等自建书库，以及古登堡计划这类公版书站都提供。
- **WebDAV 文件夹**：NAS、Nextcloud、坚果云、Alist 等，书就是文件夹里的文件。

灵阅只预置公版书的古登堡计划，其余由读者自己添加。

## 读者看到的

- “我的 → 书源”：添加、编辑、删除书源。类型选 OPDS 或 WebDAV，填地址，需要时填用户名和密码，可以“测试连接”。
- 点一个书源进入浏览页：
  - OPDS：一层层的分类，书有封面、作者、简介和可下载的格式；书目支持搜索时顶上有搜索框；分页的书目滚到底自动加载下一页。
  - WebDAV：文件夹和灵阅能读的书（TXT、EPUB、MOBI/AZW3、FB2、PDF、CBZ、Markdown），显示大小和修改时间；顶上的框筛选当前文件夹。
- 点“下载”：下载后走和本地导入一样的流程（解析、建缓存、去重），加入书架。已在书架上的书显示“已在书架”。
- **检查更新**：书架长按“刷新”。来自书源的书会从原地址重新下载，内容变了才替换，阅读进度、书签批注按原文找回位置。

## 实现

- `remote/Catalog.kt`：书源的类型、名称、地址、账号；存在 `catalogs.xml`（SharedPreferences），排除在系统备份和换机迁移之外，
  也不进灵阅自己的备份（里面有密码）。
- `remote/RemoteClient.kt`：OkHttp。HTTP Basic 认证只加在和书源同一主机、同一端口的请求上（网络拦截器逐跳检查，
  重定向到别的主机不带密码）。WebDAV 列目录用 `PROPFIND`（`HttpURLConnection` 不支持这个方法，所以引入 OkHttp）。
- `remote/Opds.kt`：OPDS 1.x（Atom）解析：导航条目、获取链接（`http://opds-spec.org/acquisition*`）、封面缩略图、
  `rel="next"` 分页、搜索（OpenSearch 描述文件或 Atom 链接里的 `{searchTerms}` 模板）。相对地址按所在页解析。
- `remote/WebDav.kt`：`PROPFIND Depth: 1` 的请求体和 `multistatus` 解析。
- `Library` 打开来源时，`http(s)` 地址交给书源客户端下载，其余仍走 ContentResolver；书的来源地址就是下载地址，
  所以“刷新”自然变成“重新下载、比对、替换”。
- 网络安全配置允许明文 HTTP：局域网里的 NAS、Calibre-web 常是 `http://`。添加书源时，`http://` 地址配了密码会提示密码明文传输。
  AI 助手的客户端仍只接受 `https://`。

## 暂不做

- OPDS 2.0（JSON）；摘要认证（Digest）；需要登录表单的书库。
- 后台定时检查更新（联网都由读者触发）。
