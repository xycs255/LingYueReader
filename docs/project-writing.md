# 项目包写作

写作围绕作者已经建立的项目包展开：先确定本章任务，再创作、审读和修订。软件负责材料分工、版本与检查记录，章界、关键选择和作者定稿权仍由作者掌握。

## 手机上从哪里进入

作品页最上面是全书进度：进度环中间是总字数，环是定稿章数占总章数，旁边写“定稿 N / 共 M 章”，设了每天码字目标时再写今天写了多少。下面的章节色块带每章一格、按卷分组：空心框是细纲、下半截实心是草稿、中间留空的是修订、整格实心是定稿（锁定），右上角小红点是有正文还没整理进设定包的章；点一格打开那章，长按弹出章节菜单。读屏时每卷念一段“第一卷 30 章：定稿 12、修订 3、草稿 15，2 章没整理”，每章可从操作菜单里打开。再下面是四张大卡片“继续写”（上次写的章）、“设定包”（几份文档）、“故事账本”（几条伏笔没收）、“写作 AI”（服务商或未设置），直达日常任务。“规划树”把总纲、卷、章和细纲卡画成一棵树：卷上有定稿进度条和字数；章上有状态记号、字数（检查规则写了篇幅时有一条字数小条，超出变色）、“有细纲 · N 拍”“AI 拟的·待确认”标签，账本里这章埋下、计划这章收的伏笔各一个小记号，点了去账本并筛到这一章。点章写正文，点章右侧的卡片图标直接进这一章的细纲卡；点卷折叠或展开。长按章不挪开、松手弹出菜单（改名、改状态、移动或删除）；长按后拖动就是调顺序：拖着的章浮起来跟着手指，落点有一条线，可以拖到别的卷，拖到屏幕上下边缘列表会自动滚，拖回原位松手不改。松手后底下提示“已把《X》移到第 N 章”（固定了细纲章号时写“移到目录第 N 个，章号仍按第 X 章”），点“撤销”换回原来的顺序；连拖几次只留最新一次的提示，撤的总是最近这一次。如果之后又移动、加删过章，撤销不会覆盖，提示直接拖回去。定稿只锁正文、不锁顺序。当书预览过的作品挪了章，再预览时书架上那本书的阅读进度、书签和划线按章换到新位置（预览的 EPUB 里记着各章是哪一章），分卷各有“第一章”这类重名的章也不会停错。移动时章号的处理：账本、设定包（细纲、伏笔表、察觉表）都按“第几章”写，章名里写了“第X章”或细纲卡填了细纲章号的章，章号不随位置变；两样都没有、按目录顺序算章号的章，作品里有账本或设定包时会把原来的章号自动写进它的细纲卡（“细纲章号”），账本和设定包里的“第几章”仍指着原来那章，提示里会写“N 章固定了细纲章号”，撤销时一并清掉。细纲章号写的是“楔子”“番外一”这类读不出数字的，章号也按目录走，同样会固定，写成“第N章（楔子）”，撤销时换回原来的字。撤销先换回目录顺序、再清细纲章号，中途写不成会退回撤销前的样子，章号不会错位。需要连续调整或用读屏时，先点“调整章节顺序”，再用每章右侧的上移、下移箭头；点“完成调整”退出。原有的预览、变更登记、伏笔和检查规则仍在“更多功能”中。

编辑器键盘上方（键盘收起时是底部）一行：左边“写 / 查 / 整理 / 更多”四个标签，右边 ✦ 推荐。点标签在上面展开一排大图标、再点收起：“写”有 AI 写…、灵感（书灵）、整章草稿、改稿（润色、更生动、扩写、缩写、挑错、去 AI 腔、按要求改、读者点评）、标点；“查”有问题、本章资料、故事账本、三道审稿；“整理”有细纲卡、这章写完了（定稿的章不显示）、自动排版、历史版本；“更多”有章节状态、改章名、预览本章、听本章、写下一章（最后一章才有）。右上“⋯”只留三道审稿、整理本章进设定包、从范本找写法、设定包；上一章、下一章是顶栏章名两边的箭头，到头的一边变灰。选中文字后系统菜单里也有润色、扩写、缩写、去 AI 腔（选中的命中了才有）、问 AI。键盘弹出、屏幕矮时展开的那排和标签合成一行，正文多留几行。第一次打开新编辑器时提示一次“菜单挪到底部了”。

✦ 按光标位置给 1–3 项，第一项显示在底栏上一点就做，“+N”展开其余：选中文字是润色、缩写或扩写、去 AI 腔；空行、段末是写第 N 拍、AI 接着写（不弹面板，从光标处写下一场）；章末看着写完了（节拍都写过，或字数到了、接近检查规则里写的下限）再给“这章写完了”；段中间是润色这段、扩写这段。下面说的是 ✦ 的第一项怎么定：空章建议“AI 写整章草稿”（细纲卡缺事实或节拍时理由写“缺细纲、节拍也行：AI 先拟、先拆，再逐拍写”），选中文字建议改写，修订章建议审稿；本章细纲卡还有没写的拍时建议“写第 N 拍”，一点就从光标处写这一拍，不弹面板（3 个方向按作品记住的，范本按“AI 写”面板里的开关）；没有可写的拍、看着已经写完了（细纲卡有节拍且都写过了，或字数到了检查规则里写的字数下限）时建议“这章写完了”，一点进收尾页；其余是“AI 接着写”；AI 未设置或章节已定稿时，先指向设置或解锁。生成中和待处理的 AI 结果只显示状态，采纳、撤回仍要到上方的结果面板操作。推荐用淡强调色底，不抢正文；还没设置写作 AI 时只是一枚描边的“设置写作 AI”次要按钮。推荐会随光标、选区及章节状态变化，不会自行发请求或采纳稿件（“写第 N 拍”是作者点了才写，“这章写完了”只打开收尾页）。

编辑器查出来的问题只有一个汇总的地方：**问题面板**。顶上那行章名下面写着“N 处问题”（提醒色），点了打开；底栏“查 → 问题”也打开它，“查”上挂着问题数。面板列出本章的四类问题：**规则**（设定包检查规则的命中，本机算；一条规则一条，有几处时“跳到位置”依次选中）、**AI 腔**（内置清单和我的黑名单的命中，一处一条，能“跳到位置”“以后都不要”）、**建议**（写作建议和去 AI 腔给出的改法，能“改”“忽略”“某类不提”）、**审稿**（本章最近一次三道审稿里事实关、写法关还没处理的，能“跳到原文”“已改”“不改”“按这条让 AI 改”，标的结果写回审稿结果，审稿页上看到的是同一份）。规则关的命中和“规则”重复，不在“审稿”里再列，审稿页上规则关也只写条数和“在编辑器的‘问题’里看”。顶上的分段控件按“全部 / 规则 / AI 腔 / 建议 / 审稿”筛选，每格带条数，没有的类不显示；“全部”按在正文里的先后排，整章的（字数不够这类）在最前。底下一排按筛选给“去 AI 腔”“管理规则”“三道审稿”。写作建议正在查、没查成、今天次数用完了，去 AI 腔正在去、没成，都写在面板顶上。正文里的底色和划线、光标落上去时键盘上方的那一条（写作建议条、规则提示）照旧，就地处理用；面板是汇总。本机检查规则只在这几处出现：问题面板、定稿和收尾页的提醒、检查规则页的“检查全书”、AI 写整章草稿页候选稿上的“N 条不合规则”。

AI 工具条上没有“矛盾检查”了：它和三道审稿的事实关做同一件事，前后对不上的去跑审稿。写作建议也不再查“设定”这一类（同样交给事实关），只查错字、规范、口吻；旧设置里勾过的“设定”读的时候忽略。

**让 AI 在光标处写正文只有一个入口：“AI 写”面板**（底栏“写 → AI 写…”；推荐的“AI 接着写”“写第 N 拍”不弹面板，直接按记住的设置写）。面板从上到下：本章细纲卡有节拍时先列“写这一拍”（写过的打勾、淡一点，默认选第一拍没写的），没有节拍时这里是一行“本章还没有节拍 · 先拆节拍”，点了进细纲卡拆；“写多少”：写下一场、写到本章结尾、写 500 字左右、按要求写…；“出 3 个方向的版本（花费约 3 倍）”，只对写这一拍、写下一场有效，按作品记住；书灵里选了范本时，最后一行“照范本写法：〈范本名〉”（默认开），开着时无论哪种写法都照范本的手法写，写完照样核验没有照抄原文。选好点“写第 N 拍”或“开始写”。写的字先浅色显示在光标处，采纳才进正文。进草稿页、先审再放进正文的叫“AI 写整章草稿”，从底栏“写 → 整章草稿”进。

**书灵**只管两件事：**问主意**（接下来怎么写、细节和描写、起名、卡文了、随便问；起名、随便问先问一句，结果在 AI 面板里看，可以插到光标处，不改稿子；定稿的章也能问）和**选范本**（选择、换、不用）。写正文不在书灵里。

故事账本可按“人物 / 伏笔 / 知情 / 全部记录”查看，并选择看到哪一章。人物卡按方面显示该章可见的状态，点方面登记新状态时要填写生效章（章号都用 － ＋ 步进器调，也可点数字直接输入；可不填的空着就是“不填”）；“看到第几章”章多时可拖“快速定位”滑条滚到某一章；伏笔卡可调计划收章；知情格点开后可查看已有来源，登记新知情必须填写获知章和消息来源。这些图形操作修改的是账本记录，旧章状态仍保留；设定包的原始伏笔计划不会被静默改写。图形操作后可在账本页撤销上一步；若记录又被修改，撤销会拒绝覆盖并提示核对历史版本。编辑、删除、调整计划收章和撤销都在保存时与账本中的当前记录比对，记录已被整理或其他页面改过就拒绝写入，提示刷新后再改，并重新读取账本。没定计划收章的伏笔显示“计划收章未定”，要先点“定计划收章”再保存，轻点滑块不会写入。只有作者知道的真相不算任何人已知；在知情格登记的新知情不是“只有作者知道”。AI 的整理提议仍须作者逐条审核、选择，才写入设定包。

整理时，和账本记录规范化后完全相同的提议直接跳过；只是看起来相似的照常列出，标“可能和账本里某条重复”，默认不勾。判断相似要求人名、数目一致，只换了一两个字的（如“林远杀了赵四”和“林远杀了赵五”）算两件事。正文写出某人得知了账本里“只有作者知道”的真相时，提议“某人从第 N 章起知道了（这条原本只有作者知道）”并默认勾上；写入后那条真相从这一章起不再要求对此人保密。只记了“第几卷起”的知情按本章卷号判断是否提前说破。依据原句去掉标点至少 6 个字，或是正文中完整的一句，且不能只是人名。一次整理写入账本只存一个“整理前”的历史版本，批量整理几十章也不会挤掉更早的版本。

## 日常使用

1. 在作品的“设定包”中导入当前材料。保留使用说明、总纲、不变量、卷章细纲、人物、察觉与伏笔，以及独立的创作、审读、修订提示词。
2. 在作品页的规划树打开目标章，确认细纲卡里的本章事实与结果、承接边界、视角、时间、推进线和章末去向。只有章组时，先手动划清这一章的起止，不把整组压成一章。
3. 从空章的智能推荐、底栏“写 → 整章草稿”进入整章草稿页。“本章写作任务”列出实际采用的材料、前文状态、篇幅与缺项。写作要求、篇幅和流程选择保留在本章草稿页，关闭重开可继续修改；发起请求时才用于本次任务，不修改设定包。前章尚未定稿时，写前由作者确认是否按细纲已定结果承接。
   细纲卡可以再细一层“节拍”：一行一拍，写这一章的哪一步，行尾可写篇幅（“（800字）”）。可以自己写，也可以点“AI 拆节拍”按细纲卡和本章资料拆成 3 到 8 拍，看过、改过再用；AI 分的各拍篇幅加起来超过全章目标的 110%（全章目标是区间时超过区间上限）就按比例压回全章目标，作者自己写在细纲卡里的篇幅不动；拆节拍和写本章用同一个全章篇幅（本章任务里的，作者的说明、细纲、检查规则都找过）；已经有节拍时先问是否覆盖。有节拍时，“AI 写整章草稿”一拍一个请求：第一拍只写开头这一拍，后面每拍带上已写的最后约 3000 字接着写，只写这一拍、不写到下一拍；每一拍的请求都以完整的任务卡收尾（全章节拍、视角、钩子都在）；没写篇幅的拍按全章目标篇幅平均分。每拍写完，候选稿连同“写到第几拍”在同一次保存里落盘（进度记在候选稿的来源记录里，带正文指纹，随备份走），中途停下或出错只丢写了一半的那一拍，“接着写第 N 拍”从下一拍继续；节拍条数改过就请作者从头写。各拍写完再照原来审读、修订。没有节拍时一切照旧。
   **一键写本章**：草稿页的“缺细纲、节拍时 AI 先补上”（作品级，默认开，随备份走）开着时，点“写本章”“重写一版”“按改过的重写”会先补细纲卡：没有“本章事实与结果”，先用“AI 拟细纲”拟一份，只补空着的项（作者写的、从细纲文档提取的不动），存进细纲卡标成“AI 拟的”，它不再跟着细纲文档变，拟完本章任务重编一次；没有节拍，再用“AI 拆节拍”拆好存进去，标成“AI 拆的”；然后照上面逐拍写。进度依次显示“正在拟细纲 → 正在拆节拍 → 正在写第 1 / N 拍”，随时可以停：已经存下的细纲和节拍留着，下次直接从第 1 拍写；拟细纲还没回来就停，什么都不存。哪一步没成，报错里写明是拟细纲还是拆节拍。两样都有时和原来完全一样；关掉开关就有什么写什么。拟细纲、拆节拍各一次小请求，不带写正文的温度和思考开关，用量记在“拟细纲”一类；写本章前的预估把它们算进请求次数，下面注明“另加约 N 次小请求”。
   写过一版后，草稿页最上方是可折叠的“这一章是按下面的细纲和节拍写的”：列出本章事实与结果和各拍，AI 拟的、拆的挂提醒色小标签“AI 拟的”“AI 拆的”，下面“改细纲 / 节拍”进细纲卡，回来点“按改过的重写”。细纲卡页上同样挂着标签和“确认这份细纲”“确认这些节拍”；改了前六项里的任何一项、换成细纲里的、改了节拍，也算确认，标签就没了。AI 拟的、还没确认的细纲不算作者划定的章组范围。
   项目包流程里，“本章尚无明确的事实与结果”那条在一键写本章时不再拦（第一步就补上了）；别的缺项照旧先拦住，不花拟细纲的钱。只有章组细纲（“目前只有第 X—Y 章章组”）时也照旧拦，并说明一键写本章不会替作者在章组里划定本章：可以在细纲卡点“AI 拟这一章的细纲”，看过、用了再写，或自己写明本章的起止与结果。
   拟细纲防剧透：只用本章和以前的资料加上设定包里写这一章的原文，后面章节的正文、细纲卡、卷纲细纲、全书结局、“只有作者知道的”都不给；不放整份设定包、不给查阅工具（两者都能读到后面章节的细纲），章目录只列到本章。细纲卡页的“AI 拟这一章的细纲”同样如此。
   编辑器“AI 写”面板上面列出各拍（写过的打勾），从光标处只写选中的一拍；智能推荐的“写第 N 拍”一点就写第一拍没写的。采纳后这一拍记成已写，推荐跟着换到下一拍；撤回、出错不记。
   关键的一拍可以勾“出 3 个方向的版本（花费约 3 倍）”（默认不勾，按作品记住）：同样的资料、节拍、细纲和写法要求，按“冲突升级”（矛盾更尖锐，人物主动顶上去）、“按下不发”（克制，不说破，用细节和留白）、“意外插入”（一个合理的小意外改变走向，不越过细纲的事实边界、不提前写后面的事）各写一版。三版并发、各自显示，计费按三次记；结果面板上方的分段控件切换三版并显示“写着 / 写好 / 出错”，正文里的浅色预览是选中的那一版，“这段有 N 处 AI 腔”也按这一版算。采纳的是选中的那一版，这一拍记成已写；“重写”只重写这一版；“停止”三版一起停；一版出错不影响另外两版；“撤回”三版都不要。面板里的花费是三版合计。“AI 写”面板里选“写下一场”再勾这一项同样如此（写到本章结尾、写 500 字、按要求写时这一项不能勾）。细纲卡页每拍一行，可以手动勾、取消“已写”；节拍条数变了，勾全部清空。节拍不算进细纲自动提取的指纹，只写了节拍的卡照样从细纲提取前六项。
4. 导入了项目阶段模板或卷章细纲时，“创作后审读、修订”默认开启。普通作品可按需要打开。项目章关掉这个开关只是写完不自动审读、修订；候选稿仍要审读通过才能采纳，重开前后判定一致。缺少本章硬事实时先补细纲；普通衔接与对白不需要重新做开书问卷。
5. 写作结果保留为候选稿。审读先列主要问题，将有依据的必改项和可取舍的审美建议分开，并显示原句与依据。资料不足明确列为缺项。
6. 有必改项时，最多自动修订一轮；修订请求开始前先保存完整创作初稿，再对新稿重新审读。仍有必改项或缺资料时停在“需要核对”。“审读并修订此稿”可继续处理已经保存的候选稿；修订前同样把当前这一版（包括作者手改稿、上一轮修订稿）留底，可以换回。修订稿写盘后，复审失败或停止也保留修订稿，并提示“修订稿已保存，复审没完成”。
7. 作者可以用“修改此稿”直接编辑候选稿，保存后旧审读失效。“修改方向”对话框里写好新方向，点“按这个方向重写”就存下方向并直接重写一版（现在写不了时只存下方向）；输入框里的新要求只用于下一次写，不让当前稿的审读失效。“可供采纳”只表示这一次流程未留下必改问题。作者通读后选择“放进正文”；原稿先存历史，章节仍不是定稿。故事账本的变更仍需在“整理进设定包”中逐条查看、选择后写入。

## 这章写完了

写完一章，收尾在一页里做完：点“这章写完了”→ 收尾页点“开始”→ 等结果 → 点“完成收尾”。入口有两处：编辑器底栏“整理 → 这章写完了”，以及光标在章末、看着写完了时的 ✦ 推荐；定稿的章都不显示。进收尾页前先把编辑框里的正文存下，收尾按存盘的正文做。

开始前是四个勾选项，按作品记住（随作品的 AI 设置存盘、备份）：**定稿**固定勾上、不能取消；**整理入账**（新设定、冲突进设定包，人物状态、发生的事、察觉、伏笔、时间进故事账本）和**写本章摘要**默认勾，没设置 AI 时不能勾，旁边写明原因（整理还要联网的服务商，本机模型不能勾）；**顺带三道审稿**默认不勾。这章有采纳进正文的 AI 原稿时多一项**从这章的改稿里学**，默认勾（见下面“从改稿里学”）。**整理交接卡**默认勾，要联网的服务商（没设置 AI、本机模型时不能勾，写明原因），见下面“章与章衔接”。本章还有不合检查规则或 AI 腔的地方时，多一行“还有 N 条不合规则、N 处 AI 腔”和“回去看看”（回编辑器），只提醒，不拦。

点“开始”后一步步显示状态（等着 / 在做 / 好了 / 出错 / 不做），可以停：
1. 勾了审稿就先审，用的是审稿页那套三道审稿，结果照常存下。审出还没处理的问题时停下，提示“审出 N 条问题”：“回去改”进审稿页，改完回来接着收尾；“不管，继续收尾”往下走。
2. 整理入账和写摘要**合成一次请求**：整理的提示词里多要一个 summary（要求和单独写摘要一样：150 到 300 字，只写事实），整理结果和摘要一起回来。这次请求算在“整理进设定包”的用量里。章太长、整理时分了段的，最后一段概括不了全章，摘要另发一次写摘要的请求（和细纲卡“AI 概括正文”同一个请求，用量照旧算在规划里）；模型没回 summary 时也另发一次。只勾了摘要时只发写摘要的请求。哪一步没成就停在那里，“重试出错的步骤”只补没成的。
3. 勾了“整理交接卡”就整理这一章的交接卡，整理好直接存下（不用再确认），确认页上说一句结果；没成只写原因，不拦收尾。你改过的交接卡不盖掉。

全部好了以后在同一页确认：
- **本章摘要**：可以改的文本框，预填 AI 写的。细纲卡里已经有摘要时，先列出旧的，给“用新的 / 留旧的”，默认留旧的。
- **整理结果**：和整理页同一套条目列表，默认勾选规则照旧（冲突、可能重复、前面章已有的默认不勾），点开能改、依据点了回正文。超过 6 条时先折叠成一行“新设定 N 条、账本 N 条、冲突 N 条”，点开逐条看。

点“完成收尾”依次做这几件事：写入勾选的整理条目（同整理页：先存历史版本、记变更登记、这一章记为已整理）；把摘要写进细纲卡（只改摘要这一项，等待期间在细纲卡页改的别的项不动；进确认以后摘要又被改过的，不盖掉，停下请作者再选）；记下勾了的学到的规则（勾了“从这章的改稿里学”时）；把章节设为定稿（存历史版本、记一笔定稿登记，正文锁定）。哪一步没成就停下，列出已写好的几步和没成的原因；“重试剩下的步骤”只做没成的和后面的，已经写进去的不再写一遍。只勾了定稿时，点“开始”直接到确认，“完成收尾”就是定稿。这条流程里不再弹“要不要顺手整理进设定包”，因为整理已经做过了。

收尾进度存在应用里：等结果时离开这一页（比如回编辑器、去审稿页）再回来，进度还在；应用被系统关掉就从头来。同一时间只收一章：一章还在收尾（在跑、审出问题等着选、没成等着重试、等着确认、正在写入）时去另一章点“这章写完了”，收尾页上写“《某章》正在收尾，等它完成或先停下”，可以“去看看”，或者“先停下它”（丢掉它这次的进度，已经写进去的不受影响）；正在写入时不能停，写完自动轮到这一章。写入时出了意外（比如设定包太大、内存不够）也退回确认页，说哪一步没成，再点只做剩下的。原来的单独入口照常可用：章节状态对话框定稿（定稿后仍会问要不要整理）、“整理本章进设定包”、作品页的批量整理、细纲卡的“AI 概括正文”；这几处的整理请求不要摘要。

## 章与章衔接

AI 主笔、作者来改时，新的一章常像重新起了个头：场景跳了，情绪断了，上一章的悬念没接上。写本章开头的请求现在带两样东西。

**上一章结尾。** 普通作品照旧带上一章结尾（最后 800–1500 字，从完整的一段起）。项目包流程以前只认定稿：上一章没定稿时一个字都不带，只写“以细纲结果承接”，AI 连写几章、还没定稿时每一章都看不到上一章怎么收的尾。现在上一章没定稿也带它现在正文的结尾（同样的截法和长度），标题写明“上一章（未定稿，只用来接住场面和语气；事实以细纲卡和已定资料为准）”；上一章是空章照旧不带。“已定前文”的规矩不放宽：本章任务里它和“用户已定前章结尾”分开放，审读证据里单列一份“未定稿的上一章结尾”，FACT、CRAFT 都不能引它，审读请求里也写明它只用来看开头接得顺不顺；改了上一章草稿，本章任务的指纹跟着变，旧审读失效。范本核验、防剧透照旧。

**交接卡。** 每章一张，记这一章结尾时的状态，给下一章用：场景（在哪、什么时间）、在场人物（各自在做什么、什么状态）、情绪基调、没说完的话和没解决的悬念或冲突（最多 3 条）、章末钩子（细纲卡里写了就以细纲卡为准）。
- 本机能抽的先在本机抽：从结尾几段里认人名（人物档案和账本里的人）、最后出现的地点（账本里记过的“位置”）、结尾那段里没答上的问话；拿不准的（人物在做什么、情绪基调）空着，不瞎填。
- 有 AI 时顺手整理两次：“这章写完了”收尾时一项（默认勾，见上面）；一键写本章、从本章开头写之前，上一章还没有交接卡、或者整理之后上一章正文改过，先整理一次，进度条上显示“正在整理上一章的交接…”，能停。整理请求只给上一章最后约 3000 字和细纲卡的钩子，不带温度，官方 DeepSeek V4 上关思考，只要 JSON，用量算在“整理进设定包”里；回的不是约定的 JSON 就如实说一句，照常写，只是不带交接卡。编辑器里在章首写不为它另发请求：用存着的，没有或过期了用本机抽的。
- 按章 id 存在作品目录的 handoffs.json 里，连同整理时正文的指纹和章的修改时间（判断过期：修改时间没变不读正文；变了才比指纹）。整份写临时文件再改名，随作品备份（旧备份没有这一项时保留本机的），删章时一起清掉。移动章节不受影响；“上一章”永远按目录里的前一章算。读盘、比指纹都不在主线程。
- 写本章开头的请求（整章、逐拍写的第 1 拍、编辑器里在章首写）在“上一章结尾”后面加一节“上一章交接”，任务卡里加一句“开头先接住上一章的场面和情绪，再往下走；悬念可以先放着，但不能当没发生过。”接着写、写到中间、修订不带。
- 草稿页上方的卡片里有一栏“接上一章”，写之前也显示，点开看交接卡；“改”能改各项，改过的标“你改过的”，之后不被自动重新整理盖掉（正文又改了会提醒看看还对不对），点“重新整理”才按上一章现在的正文重来（没有 AI 时回到本机抽的）。细纲卡页“上一章留下的”里多一行“上一章交接：…”，点了能改。

## 从改稿里学

作者的用法常是“AI 主笔，我来改”：每次改稿都在说 AI 哪里不对。灵阅把这些改法记下来，下一章 AI 照着写，作者不用自己写规则。

**记下 AI 原稿。** AI 写的字被采纳进某章正文时，把采纳的那段原文记下来（带时间）：草稿页“放进正文”（替换整章时这章以前记的作废）、编辑器“AI 写”的采纳、逐拍写的采纳、AI 面板“接着写”和“插到光标处”都算。编辑器里采纳 AI 的改稿（润色、缩写、扩写、去 AI 腔、审稿修复、写作建议的“改”）时，原稿里那段跟着换成 AI 改后的字（原文不在原稿里时，改后的字另记一段），收尾比对时这些算 AI 的改法，不算你的。存在作品目录的 learn.json 里，整份写临时文件再改名；每章最多留最近 2 万字、40 段，一部作品最多 20 万字，超了丢最早的。随作品备份；旧备份里没有这份时恢复照常，保留本机的，但正文被备份换成旧版的章，这章的原稿和计数清掉（“不再提”和“这段不行”的次数照留）。删章时这章的原稿和计数一起清掉，删作品时整份删掉。读写都不在主线程。

**收尾时比对（本机，不花钱）。** 勾了“从这章的改稿里学”，收尾时把这章的 AI 原稿和存盘的定稿按段对齐（同草稿页的段落对比：相同的段一个记号按段比，一万多字的章也只是几百段，在后台算），对不上的那一块里按相似度配对：配上的是作者改过的段，没配上的原稿段是整段删了，定稿多出来的是作者自己写的，不管。比对前先看每一块原稿（一次采纳记一块）在定稿里还找不找得到：一段都找不到（原样的没有，改过的也不像）的整块不算，那是采纳后撤销、删掉重写或换了一版的，不当成“作者习惯整段删”；同一处先后采纳过两版时，定稿里的段归后采纳的那块。然后数这几种改法：某个说法被删、被换掉；对白后的解释句被删；长句被拆短；段落整段删掉、被压到六成以下。阈值（宁可少提）：
- 黑名单词：同一个说法累计被删、被换 3 处以上，而且在至少 2 章里出现；每章还要求删的比定稿里留着的多（定稿里还在用，说明只是那一处不合适）。只要 2 到 12 个汉字：再长就是整句，进黑名单没用。
- 写法规则：对白后的解释句、长句拆短，一章里至少 2 处、占这章“有机会这样改”的段落 25% 以上；整段删、压短，一章里至少 2 处、占这章 AI 段落 15% 以上。同样要在至少 2 章里站得住。
跨章的计数和原稿存在一起；同一章再收尾一次是重算这一章的数，不叠加。

**AI 归纳（有 AI 时，可选）。** 用联网的服务商时，再挑几对“AI 原段 → 你改后”（改得多的在前，整段删的也算，一共 6000 字以内），请 AI 归纳最多 5 条写法规则，只要 JSON。这个请求不走写正文的路径：不带温度，官方 DeepSeek V4 上关掉思考；用量算在“整理进设定包”里。回的不是约定的 JSON 就如实说“没能归纳出规则”，不把原文当规则；规则写成了正文原句、黑名单词在原段里找不到的，都不要。没成不拦收尾，本机比对出的照样给。

**你来勾。** 确认页上“从改稿里学到的”一条条列出：“黑名单词：「……」”加进我的黑名单，“写法规则：……”加进“从改稿学到的”（最多 50 条）。每条下面一行例子“原来「……」→ 你改成「……」”，看得懂为什么提这条；旁边写着怎么来的（几章里删了几处、AI 归纳、“这段不行”点了几次）。本机比对和“这段不行”来的默认勾上，AI 归纳的默认不勾，下面多一个“不要”。点“完成收尾”时勾了的才记下；本机比对和“这段不行”来的没勾就记进“不再提”，AI 归纳的点了“不要”（或勾上又取消）才记，没看就完成的下次还能再提；AI 提的黑名单词和本机统计的同一个词分开记，不要 AI 的那条不会挡掉本机以后统计出来的。“不再提”的以后不重复提；已经在黑名单（或被黑名单里更短的说法盖住）、已经在学到的规则里的也不再提。

**用上。** 写正文（编辑器里写、写整章草稿、逐拍写、本流程的创作和修订、压篇幅、“这段不行”的重写）时，写法要求后面带一节“作者改稿里学到的”，取最近 12 条；润色扩写这类改稿也带。审稿、审读、拟细纲、整理、摘要不带。作品 AI 设置“AI 腔”里多一行“从改稿学到的”，样子同“我的黑名单”：能看、能删、能手动加。

**草稿页“这段不行”。** AI 写整章草稿页的当前稿每段下面有“这段不行”。点了选原因，可以多选：太死板、啰嗦、人物不像、没情绪、太水、其他（可以写一句）。AI 只重写这一段：走写正文的路径（写正文的系统提示、写法要求、温度和思考开关），前后各带一段作语境，原因换成具体的改法要求（比如“没情绪”是“给在场人物补一句当下的情绪或动作……”）。写好了以“原段 / 新段”对比给你看，“采纳这段”只换草稿里这一段，原来那版留着能“换回修订前那一版”，审读要重新做；“放弃”就不换。草稿在写、在审读、在重写别的段时按不了。照范本写的稿子不能绕过范本核验：请求前确认范本没变，写回来把换好的整稿再核一遍有没有照抄范本（照逐拍写），采纳时再核一次，没过就照实报错、草稿不动。原因按作品计数，采纳了重写才算一次（没写出来、停下、放弃的不算），同一个原因累计 3 次以上，下次收尾学习时提成写法规则（比如“写对白时给人物补一句当下的情绪或动作”）。

作品的“写作 AI”设置分两层：常用的直接列出（服务商、设定包、写作范本、文风、这部书的口味、文风范例开关、写正文的温度、写正文时先思考、查 AI 腔、我的黑名单、从改稿学到的、写作建议开关和三类子开关（错字、规范、口吻）、AI 记录、用量）；知识库上限、本章资料上限、写作建议的两次至少隔和一天最多、文风范例的最多带和“没有定稿章时用字数最多的章”“看看挑了哪几段”、学你的改法的计数和清除、最近一次发给 AI 的内容，收在最下面一行“高级设置”点进去的二级页里。值和存储都没变。排版设置默认只露“输入时自动排版”和“引号风格”，一键排版的其余 10 条规则收在“更多排版规则”里，点开才列出。

设置里可以选“写正文的温度”：服务商默认（不传这个参数）、稳一点 0.7、略稳 0.9、标准 1.0、放开些 1.1。越高越不套路，也越容易跑偏；最高只给到 1.1——DeepSeek V4 关掉思考时温度原样起作用，1.3、1.5 会写成一串读不通的字。旧版本存的 1.3、1.5 读出来按 1.0 算，发请求时也不超过 1.1。它只用在写正文、改正文的请求上：编辑器“AI 写”面板的各种写法和写这一拍、AI 写整章草稿与逐拍写、本流程的创作阶段、润色/更生动/扩写/缩写/续写/按要求改，以及多方向版本，还有本流程的修订（修订稿也是正文，和初稿用一样的温度和思考开关，文风才不会两样）；挑错、审稿、本流程的审读、拟细纲、拆节拍、摘要、整理、写作建议、去 AI 腔都不用。只有 OpenAI 兼容接口的请求会带上 temperature；Anthropic 接口和本机模型不带。服务商以 400 拒绝 temperature 时（推理模型常见），去掉它自动重发一次；DeepSeek 思考模式会忽略这个参数。

同一组里还有开关“写正文时先思考”，默认关，用的范围和温度完全一样。DeepSeek V4 默认开着思考：思考的 token 也算进输出上限，而且思考模式会忽略温度。关着时，发给官方 DeepSeek（api.deepseek.com）V4 Pro、Flash（含旧名 deepseek-v4-flash）的写正文请求带上 `"thinking":{"type":"disabled"}`，更快、更省，温度也才起作用；开着时不写这个参数，照服务商默认先想再写，贵、慢，适合复杂场面。别的服务商、别的模型一律不写。不写正文的请求里，整理入账（含收尾时整理加摘要那一次）和写本章摘要在这些 V4 上也带 `thinking: disabled`、不带温度：它们只是从正文里摘事实、写一段概括，用不着先想，而整理的输出上限只有 4096（加摘要 5120），开着思考会被思考吃光、报“回答太长”；审稿不关，要判断前后矛盾，思考有用，也不设输出上限；其余不写正文的请求照服务商默认。温度被拒重发时只去掉温度，思考的设置照旧。编辑器里写一段平时把输出上限压到 8,192 token；开着思考、又是能开关思考的 V4 时改用整章的上限（见下文），免得上限全用在思考上。

AI 一个字没写出正文时如实报错，不当成“写了 0 字”给人采纳：到了输出上限说“模型把这次的输出上限都用在思考上，没写出正文”（开着“写正文时先思考”、模型又能关时再提示可以去关掉），正常结束却没有字说“AI 没有写出正文，再试一次”。编辑器里写（三个方向时只那一版出错）、AI 写整章草稿、逐拍写、本流程的创作阶段都这样；花了多少照常显示。

这条流程会发起多次模型请求；工具查阅还可能增加请求。“写本章”发起前，页面按当前模型和实际组装的**首轮**请求估算输入 token；有明确输出上限和单价时，也显示费用范围，否则说明上界或价格暂不能估算。页面还会提示规划上下文是否可能超出预算。费用粗估不假定缓存命中，Anthropic 的高值还考虑首次缓存写入；审读、修订、工具多轮和接着写的费用不在首轮估算内。它是提醒，不是硬额度或服务商账单，超出规划预算也不会自动截取材料。但任何一次写作 AI 请求，要发的内容（按真发的请求体估，不算输出）本身就超过模型的上下文（DeepSeek、通义、Kimi、智谱按 128K token，Claude 按 200K，局域网模型按 32K；自定义服务商和本机模型不拦）时，发之前就拦下，提示“资料太多，超过模型上限”，不白发；“看发给 AI 的内容”仍能看到这次要发什么。界面在完成后显示服务商返回的用量（缺失时标明估算），创作、审读和修订分别计入对应功能，候选稿记录汇总本次用量。

开启“写作时给建议”后，停笔约三秒才检查打开本章后改过的段落。若上一轮还没结束，灵阅只排队最新正文，成功完成后再检查，避免旧正文的建议覆盖新稿。模型回答缺少要求的 `issues` 数组，或条目的段落编号、原文和改法字段格式有误时会显示失败，相关段落不会标成“已查”；为了避免自动重复付费，不会立即重发，下一次停笔可再试。

## 导入 Markdown 项目资料

在“设定包”中可选单份 `.md` / `.markdown`、包含这些文件的文件夹，或项目包 ZIP。导入预览列出相对路径、原文开头、识别出的资料类型和导入后的标题；同名文件可以先改标题，避免把不同卷的细纲看成同一份。空白文件默认跳过，也不能手动选中覆盖已有资料。发现无法识别的字符时，预览会提示核对编码。设定包中保存 Markdown 原文，导出 ZIP 后仍是 `.md` 文档；导入不会修改所选源文件。本地目录、分章和事实提取会跳过代码围栏中的示例；AI 查阅仍可看到原文，候选稿需要作者核对。

一级到多级标题会进入按需查阅目录，重复的“第一章”可按“第一卷 › 第一章”这样的完整路径定位。普通 Markdown 表格、带转义竖线的单元格和不写首尾竖线的表格可用于人物、知情与伏笔资料；长段落分块时保留全文。AI 查阅返回原文片段，作者仍须核对候选稿和账本提议。

## 写作范本

在“作品 → 写作 AI → 写作范本”导入作者自己选择的 TXT 或 EPUB 小说。范本按书、章单独存放；它不是这部作品的设定、已发生正文、写作规范或创作提示词。导入不会发起 AI 请求，也不会改变正文。书的章界和开头片段可以先预览，选错章时在发起分析前更正。TXT 最大 32 MB，EPUB 最大 64 MB；EPUB 只读取正文文字，插图不解压。超过上限的文件在读取前就拒绝，手机内存不够时提示文件太大，不会闪退。“第一卷 风起 第一章 少年”这类卷章同行的标题保留章标题；“第一部手机……”这类正文句子照常当正文。

在目标章的编辑器里打开“从范本找写法”，选择范本书、对应章节和分析范围，再明确点“分析”。选“整章”时，AI 可以分析本章的开篇、全章叙事安排及对白；选择“开头”“结尾”或自选范围时，只能分析实际选中的文字，不能声称看过未提供的段落。整章超过上下文上限时要求作者缩小范围，不偷偷截断还报告整章结构。界面预览将发送的范本片段，分析结果标明书名、章名与范围，短引原句佐证观察，并把可借鉴的叙事手法转换成当前章的具体选择。

分析是给作者参考的独立记录，不自动改稿、套用范本人物和情节，也不作为故事事实进入设定包或故事账本。重新导入范本或修改目标章资料后，旧分析的来源和目标指纹可用于提示结果已过期。范本分析单独计入 AI 用量；保存的分析可以回看，不会因为打开页面重新发请求。每部作品最多保存 100 份分析，存满时在发请求之前就提示先删旧分析；删除章节时，指向这一章的分析一起删除。分析引用范本原文每处不超过 30 字、合计不超过 120 字，提示词与检查用同一组数字；结果因此或其他原因没能保存时仍留在页面上，可以复制。用范本写出的候选稿，只有和范本连续相同超过 30 字，或 12 字以上的相同片段合计超过 120 字，才算照抄。

## 资料的边界

- 本次明确要求优先。目标章细纲规定本章时地、在场与知情、资源权限、选择、损失、结果和章界；已定前文规定实际发生的行动。硬事实冲突要列出处核对，不用一句“优先级”掩盖。
- 总纲与合订本补核本章涉及的跨章固定设定，不要求将整卷逐项演成正文。
- 同版独立文件与合订本内嵌副本只算一份。不同版本不自动累加事件；发现独立与内嵌版本有差异时显示提示。
- 创作、审读、修订模板只在对应阶段进入工作说明。工具可查的文档也遵守同一阶段选择，避免读文档时重新混入另一阶段的模板。
- 只有作者明确标为“定稿”的前章正文，才作为项目写作的已发生前文；否则明示“以细纲结果承接”，另带上一章现在的结尾，标明未定稿、只接场面和语气，审读不拿它当依据（见“章与章衔接”）。规划、未定样章、候选稿与待核增量不会因为流程通过就成为已定事实。
- 联网项目写作与审读需要按需查阅设定包时，若所选模型不支持工具调用，本次流程明确失败并保留候选稿，不把未查到的资料当成已核对。“整理本章”例外：它只产出待作者勾选的提议，设定包常用部分和本章资料都在系统提示里，模型不支持工具时去掉工具整理，结果页注明“这次没能查设定包，结果可能漏掉冲突”。短回复的“测试连接”不能证明模型已支持设定包工具或长上下文。
- 用户已定的前章之后、目标章之前的资料按章取用。人物知情与未来信息分开；AI 查正文时保留原章号并限于可用的已定正文。
- 写正文（创作、修订、编辑器里写）时，系统提示里不整份放知识库，也不放整份本章任务包：只有作者写给 AI 的说明（工作说明和这一阶段的提示词，去掉整章字数）、作者的写作规范和检查规则（只放一份，去掉字数一行）、按本章挑的资料。挑资料时不带本章之后的章节细纲、后面卷的细纲、总纲和卷纲细纲（本章细纲在任务卡里，前面的章有前情摘要）、写到后面章节或卷的句子、写结局和谜底的句子、人物“变化”“结局”这类条目和“只有作者知道的”；人物还不知道的事只列出场人物的，不带章号。故事账本快照里后面才发生的照样列着，好让正文做铺垫，但不说第几章：人物还不知道的写“这件事林月现在还不知道，后面才会知道。这一章别让她知道或说破，可以留个引子”，没收的伏笔只写哪章埋的，加一句“这条伏笔后面才收，这一章可以轻轻提一笔，别收”。写正文时查阅工具照旧能查全部资料（包括后面的细纲和结局），工具说明里写明：后面的剧情只用来埋伏笔、做铺垫，可以留细节、留疑点、点到为止，不能让人物提前知道、不能说破、不能写出后面才发生的事。拟细纲、拆节拍不在此列，仍然不用后文。资料都不带“[来源 …]”编号；细纲文档和手改细纲卡不一致时只给手改卡那一版，提示只给作者看。审读也不再整份放知识库：系统提示里是编辑助手的身份、作者的工作说明和章节审读提示词、本章任务（细纲卡、已定前章结尾，本章资料用写正文挑的那一份、换成核对的说法，含账本快照）和一张能查的资料清单，请求里是待审的整章、作者的写作规范和检查规则（只放一份）、判断标准和出处要求；其余资料让模型用 read_doc / search / read_chapter 查，查阅结果里带“[来源 …]”编号，审读意见照旧要给来源编号和来源原句，本机照旧逐条定位。约一百二十万字的虚构设定包，审读一次从约 18 万字降到约 1.5 万字，修订约 1.3 万字。本章资料里“埋下还没收的伏笔”最多列 30 条（先列写到出场人物的、计划回收最近的），其余只说一句有多少条、要核对时查伏笔表：伏笔表几百条时，以前光这一节就近两万字。

## 写法与篇幅

写正文的请求（编辑器里写、AI 写整章草稿和逐拍写、本流程的创作和修订）身份是“和作者一起写这部小说的合写搭档，负责先写出好看的初稿，作者再改”，不是编辑助手。请求里依次是：前文（上一章结尾只留最后 800–1500 字、从完整的一段起；接着写时是已写的最后一部分；编辑器里是光标前后）、范本的要求（选了范本时）、这部书的口味、作者的文风要求、文风范例、采纳过和没采纳的改法、“写法要求”、黑名单和从改稿学到的规则，**最后一段永远是“本次写作任务卡”**：第几章、视角、全章节拍（标出已写、这次写哪一拍、后面再写的、本章结尾停在哪个钩子上）、从哪里接、写到哪里停、篇幅、作者这次的要求、本章必须成立的事、这一章不写到的、时间、这一章可以埋的伏笔（账本和伏笔表里还没收、和本章出场人物或所在地点相关的，最多 5 条，每条标“只点到为止”，开头一句说明后面的事只用来铺垫；没有就不写这一节，修订时也不写），末了一句“这些事要写出来，但写成场面和对话，不要列清单式交代”。逐拍写的每一拍都带完整的卡，视角、钩子不会丢；写到本章结尾时列出剩下的拍（作者没勾“已写”时按正文估已经写到第几拍），停在章末钩子上；没有节拍时用细纲卡的事实、视角、钩子拼出同样的卡。审读请求不带写法要求和任务卡。编辑器里的“查 AI 腔”在本机按内置清单和黑名单标出套话，和检查规则分开计数，不花钱。

“写法要求”说“要什么”：人物有情绪、有心思，可以直接写他在想什么；对话像活人，有来有回、带潜台词，可以抢话、顶嘴、打岔、开玩笑；每一场都往前走，关键信息让读者明白为什么要紧；主角主动，会盘算（穿越、重生的书提一句用上历史知识）；节奏有快有慢；叙述可以有态度，偶尔吐槽、玩梗；写具体的动作、物件、声音、气味。作者的写作规范里写了同类规矩（心理写多少、句子长短、能不能吐槽）的，那一条听作者的，不同时给两个说法。去套话交给本机清单、黑名单和一键去 AI 腔，写法要求里只留一句。

篇幅顺序为本次明确要求、目标细纲、适用于本章的项目约定、检查规则。算出来的篇幅只在任务卡里说一次：写一拍是这一拍的字数，整章是全章字数，写到本章结尾是剩下的字数，都写成区间加上限，比如“约 800 字（600–1000 字，最多不超过 1000 字；宁短勿长，这一拍的事写完就收，不要为了凑字加戏）”。上限是目标的 1.25 倍；全章目标是作者写的区间（“3500 到 6000 字”）时，目标取中间、上限就是区间上限；作者的说明、写作规范、检查规则、细纲里写的整章字数，交给模型前都去掉（本机检查照旧按检查规则数字数）。弹性目标显示提醒，不据此截断自然场面；不在通用应用里固定某部小说的章数和字数。

模型照样可能写过头，所以流式写的时候本机也把关：一拍（或整章、写到本章结尾、写 500 字左右、写下一场）实际写出来的字数超过各自上限的 1.3 倍，就在下一个句末（。！？…，引号、括号里的不算，收在后引号后面）停止接收、取消请求，结果里注明“这一拍写长了，在 N 字处收住了”。写下一场卡上不写数字，本机按约 1500 字的上限把关；按作者要求写的不收。逐拍写时被收住的这一拍照常算写完，接着写下一拍；全章累计超过全章上限的 1.3 倍时这一拍也在句末收住，后面的拍不再写，草稿页提示还有哪几拍没写，“接着写”可以写完。整章草稿比全章目标长 30% 以上时（区间按上限算），草稿页字数旁标“比目标长 X%”，“你来审定”里多一项“压到约 N 字”：走写正文的路径（写正文的系统提示、写法要求、温度和思考开关）对整稿做一次精简，压好的是新的一版，可以“换回修订前那一版”；审读要重新做，没压成时原稿不动。照范本写的稿子压完对新的一版重新核验范本，通过了照样算已核验，可以接着写、审读。

照范本写时，范本只学写法，篇幅以任务卡为准：提示里写明不跟着范本的长短、节奏铺开，只写一拍时不要把范本整章的起承转合都搬进这一拍（整章范本最多带一万二千字，逐拍写时每拍都带一遍）。

DeepSeek V4 Pro、V4.1 Flash 写整章时分别设置 32,768、16,384 token 的单次输出上限，思考过程也计入此上限；达到上限或服务商中止时标记本次未完成，已收到的片段仍可供作者核对，不自动视为可采纳的完整稿。设置页的“测试连接”只发一条有严格输出上限的短请求，并不检验设定包工具与长篇写作能力；真实服务商仍可能对这条请求计费。

修订和创作一样以写法要求和任务卡收尾，带作者的章节修订提示词（不带正文创作提示词），用作品设的温度和思考开关：审读意见说得对的才改，误读原稿、和细纲对不上的不照办，意见不自动成为新设定；只在有问题的地方改，不把对白都改短，不加总结。

不套固定场次数、入口轮换、微伏笔、快慢配额或每章硬悬念，不为了凑字改动既定章界。章名由软件单独管理；内部保留纯正文，显示与导出继续使用作品的段落格式。

## 版本、失败与恢复

审读报告绑定正文 SHA-256 和实际项目资料指纹。修订后旧报告失效；资料或审读时的要求变了，旧结果也不能直接用于采纳（润色的采纳、不采纳记录不算资料变化）。模型返回错误格式或缺少依据时显示未完成，不当作“没问题”。单条意见的原句在本稿中对不上（比对时忽略空白和全角半角）：可取舍的建议直接略去；必改意见保留、标“依据未核实”并列为缺项，本稿停在“需要核对”，也不据此自动修订。整稿请求遇到拒答、内容过滤或连接中途断开（没有收到结束标记）时报错，不把提示语或半截回答存成候选稿。事实审稿意见还要求来源编号和来源原句：灵阅会检查引文是否能在本次任务、设定文档或可用的已定前文中定位；找不到的必改意见改列待核资料，不据此自动修订。**引文存在只证明来源位置，不证明 AI 对原文的解释或事实判断正确**，作者仍需核对。本机硬规则和 AI 语义审读分别记录。

作者选中的“整理进设定包”提议在写入前会用原文 SHA-256 快照复核章节正文（只统一不同系统的换行符）；改字、空白或标点后都要重新整理。对依赖原句替换或目标小节的提议，写入当前设定文档时还会重新核对锚点；原句消失、重复或小节位置不再符合预期时拒绝猜测位置，提示作者重新核对。

草稿页可在“当前稿 / 创作初稿（或对照修订稿） / 对比”之间切换查看。对比按段落标出增删；若改动过大而无法可靠对齐，就依次展示两份完整文字，不猜测对应关系。自动修订前保存的首稿会随草稿持久保留；作者可“换回修订前那一版”（再次修订时，留底的是那次修订前的稿子，可能是作者手改过的），原修订稿保留为对照，并可在未继续修改初稿时切回。切换版本、手改候选稿都会使旧审读失效；采纳前要对当前正文重新审读。

照范本写的候选稿，写出来的每一部分都核验过没有照抄范本才标“已核验”，这个标记和正文、范本指纹一起落盘（随备份走）：逐拍写每拍写完核一次；被本机收住、全章累计超限停写的照样核验、照样标；整章写到一半停下或出错留下的半章，也当场核一遍，过了就标上；某一拍没过核验时只丢这一拍，前面核验过的几拍留着。接着写、“审读并修订此稿”之前，已写稿只要过范本这一关；过不了时草稿页“范本核验”一组给出路，不只说“请从头重写”：标记丢了（手改过、换过版本，或旧版本压过篇幅）而范本没变，点“重新核验范本”重跑一遍，过了就恢复；范本变了、删了或读不到时，可以“不用范本，直接审读这一稿”：先拿范本现在的原文对已写正文跑一遍同样的核验，通过了才去掉这一稿和范本的关联（正文不动，下次写用的范本选择也清掉）并直接审读，不通过就指出哪一段和范本一字不差，范本读不到时没法查、不能去掉；实在不行才“从头重写”。

草稿正文、范本来源记录与初稿快照作为同一组保存，进程在中途退出时按保存日志恢复，避免只剩正文或只剩来源。停止、错误和重启后保留已经保存的候选正文；重写已有候选稿时，新完整稿保存前若停止或失败，会回到上一版完整稿，连同它的审读结果，本次的错误只作提示、不挡采纳；从空稿起写且只收到部分文字时，保留部分稿供核对、续写，不把它当成完整可采纳稿。需要项目审读的候选稿会持久记录这一要求，恢复后报告不自动成为通过，必须对恢复的实际稿件重新审读。

备份会一同记录可读的草稿和初稿快照，恢复前校验版本与正文的对应关系；损坏的快照不会作为有效版本覆盖本机内容。如果备份候选稿与本机候选稿不同、而本机留有初稿快照，恢复时保留本机这组草稿与初稿，并报告跳过的文件。旧备份没有初稿快照时，兼容恢复并保留可匹配的本机版本。

边写边显示：模型几个字一块地流过来，收到的正文边收边清理（只看还没写完的那一行），编辑器和草稿页最多每 150 毫秒刷新一次，不是每来一块就把整章重新清理、重排一遍；“这段有 N 处 AI 腔”、本机检查规则写完才算一次，在后台算。写正文时出了程序本身的毛病（内存不够、栈溢出、下标越界这类）不会闪退：这一次停下，界面上说“出了意外”，已经存好的几拍、上一版候选稿照旧保留；出错的位置记进“我的 → 闪退记录”（只有类名、代码位置、时间、版本和当时的界面，错误说明里的汉字都隐去，不带正文），真的闪退了也记在那里，下次打开问一次要不要复制给开发者。

编“本章写作任务”：设定包读出来、拆开合订本、按阶段筛过、挑好的本章资料，按设定包的版本（每份文档的标题、类别、更新时间、字数，文件的大小和改动时间）记一份，设定包没变就直接用，改了任何一份文档才整份重算；只记当前作品的一份。草稿页改“写作要求 / 篇幅”时，停笔半秒才重编，写本章请求预算直接用编好的那份；审读核对按审读时的要求，和页面上一样就用页面上那份，不一样就编一次留着，作者再改页面上的要求也不跟着重编；写本章请求预算按实际要发的请求数写“共 N 次请求”：写前准备（拟细纲、拆节拍）各一次，写正文一次或逐拍写一拍一次（写前才拆节拍的按 3 到 8 拍算），项目包流程再加审读、修订 1 到 3 次；同一时间只编一份，要求一样的一起等这一份，要求又改了、旧的那次没人等了就停下。逐拍写的各拍、审读、修订用开头编好的同一份任务，写完再编一次只为核对资料有没有在写的途中变。编的时候内存不够，草稿页和写正文都只提示“资料太大，内存不够……”，不闪退；遇到这句提示，先把设定包里用不到的大文档（旧版、重复的合订本）删掉或拆小。

重新生成在出现新正文前仍显示上一版候选稿；请求失败时可核对、重试，旧稿不会因请求开始而清空。正文、草稿、设定文档和故事账本在多文件保存中断后会尝试修复作品信息；尚未修复的作品不进入备份，也不会被备份覆盖。修复过的作品可以照常从备份恢复：恢复前正文、设定文档和故事账本先存进各自的历史版本，候选稿与备份不同则保留本机的；恢复成功后修复标记随之清除，以后不会每次都被跳过。任何作品从备份恢复时，本机故事账本与备份不同，也会先存进账本的历史版本（标“从备份恢复”）。故事账本若有读不出的条目，会保留原文件并停止账本修改，避免把坏条目当成空记录覆盖。导出先在应用缓存中完成，再写入选定的文件；目标文件提供方在最终写入中途失败时，仍可能留下不完整的导出文件。

软件没有代替外部技能运行脚本门禁、训练模型或部署知识图谱。界面里的“可供采纳”不是外部门禁通过证明，也不等于作者认可。
